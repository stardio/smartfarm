# 농업 자동화 통합 플랫폼 — 제품 기획서

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 (2026-11-07) |
| 브랜드명 | **미정** (상표 검색 후 확정 — 15장 참고) |
| 기반 | 이 저장소(`smartfarm`)의 1호 농장 시제품 |

---

## 1. 비전

> 관수·양액·환경제어·작물재배 설비와 **농업용 자율주행 AGV** 까지 하나의 플랫폼에서 운영하는
> **농가용 자동화 시스템**. 농장주는 휴대폰 하나로 농장 전체를 보고 제어하며,
> 반복 작업은 설비와 로봇이 스스로 처리한다.

핵심 가치
1. **통합** — 제각각인 관수기·양액기·환경제어기·로봇을 한 화면·한 기록·한 알림 체계로
2. **안정** — 인터넷이 끊겨도 농장은 계속 돌아간다(현장 자율 운전), 안전 로직은 현장에서
3. **확장** — 농가마다 다른 장비·규모를 "장치 프로파일"과 설정만으로 수용
4. **데이터** — 모든 센서값·운전 기록이 쌓여 작물 레시피·분석·AI 로 이어진다

## 2. 고객과 문제

### 대상 (가정 — 실증 후 확정)
- 1차: 시설원예 농가(비닐하우스·유리온실), 수경·양액재배 농가
- 2차: 수직농장·육묘장, 영농법인·스마트팜 단지

### 농가가 겪는 문제
| 문제 | 현재 상황 | 플랫폼이 주는 해결 |
|---|---|---|
| 장비가 따로 논다 | 관수 타이머, 양액기, 온도조절기, 환풍기 컨트롤러가 각각 다른 회사·다른 화면 | 하나의 앱에서 통합 제어·기록 |
| 현장에 있어야 한다 | 고장·이상을 직접 가서 확인 | 원격 감시, 즉시 알림(텔레그램→앱 푸시) |
| 사람 손이 많이 든다 | 순찰·운반·방제 등 반복 노동, 인력난 | AGV 가 반복 작업 수행, 설비와 작업 연동 |
| 기록이 없다 | 관수량·투입량·환경 이력이 남지 않음 | 자동 리포트, 작물별 레시피로 재현 |
| 확장이 어렵다 | 기존 설비 교체 부담 | 기존 설비에 I/O 모듈만 붙여 연동 |

## 3. 제품 구성 (라인업 안)

| 제품 | 설명 |
|---|---|
| **엣지 컨트롤러** | 농장마다 1대. 제어 판단·안전 로직·현장 화면·로컬 DB. 실내 설치 |
| **필드 I/O 함체** | 릴레이·센서 입력·Modbus 게이트웨이를 담은 표준 함체. 구역·동 단위로 현장 설치 |
| **센서 패키지** | RS485 Modbus 온습도·CO₂·EC/pH·수위·유량·토양 센서 (검증된 모델 목록) |
| **클라우드 서비스** | 여러 농장·사용자 관리, 모바일 앱, 알림, 리포트, 원격 업데이트, 레시피 |
| **AGV 연동 모듈** | 자체 또는 협력사 AGV 를 표준 인터페이스(VDA 5050)로 연결 |
| **설치자 도구** | I/O 할당·시운전·장치 검색·진단 화면 (설치기사·대리점용) |

## 5. 시스템 아키텍처

```
┌──────────────────── 클라우드 플랫폼 (브랜드 서비스) ─────────────────────┐
│ 계정·권한 · 농장 목록 · 모바일/웹 앱 · 알림(푸시) · 리포트 · 레시피       │
│ 원격 업데이트(OTA) · 시계열 DB · 분석/AI · AGV 작업 관리(Fleet)           │
└──────────────────────▲ MQTT over TLS (기기 인증서) ───────────────────────┘
                       │  끊겨도 농장은 자율 운전, 재연결 시 기록 동기화
┌──────────────────────┴───────── 엣지 컨트롤러 (농장 1대) ─────────────────┐
│ 제어 엔진(관수·양액·환경) · 안전 로직 · 규칙/레시피 실행 · 로컬 DB          │
│ 장치 드라이버(Modbus TCP/RTU + 장치 프로파일) · 현장 HMI · 설치자 도구      │
│ AGV 브리지(VDA 5050) · 로컬 알림                                           │
└──────▲ Modbus TCP (제어 전용망, 인터넷 비노출) ────────────▲ VDA 5050/MQTT ┘
       │                                                    │
┌──────┴──────────── 필드 I/O 함체 (구역·동 단위) ─────┐   ┌──┴──────────────┐
│ Modbus TCP↔RTU 게이트웨이 / 이더넷 릴레이 보드       │   │ AGV              │
│ 릴레이 → 전자접촉기 → 밸브·펌프·히터·팬·조명         │   │ 주행·장애물·안전 │
│ RS485 센서 (온습도·CO₂·EC/pH·수위·유량·토양)          │   │ 은 AGV 자체 처리 │
└──────────────────────────────────────────────────────┘   └──────────────────┘
```

### 설계 원칙
1. **현장 자율** — 제어 판단과 안전은 엣지에서. 클라우드는 감시·설정·분석·작업 관리
2. **안전은 다층** — 소프트웨어 안전 로직 + 하드웨어 차단(바이메탈 과열 차단기, 비상정지, 전자접촉기 인터록). 소프트웨어만 믿지 않는다
3. **장치 프로파일** — 장비 모델별 레지스터 표·스케일·명령 방식을 데이터로 정의. 새 장비 = 프로파일 추가
4. **계층형 데이터 모델** — 농장 → 동(하우스) → 구역 → 장치(채널). 구역 수·시스템 구성은 설정
5. **이벤트 기록** — 모든 명령·설정 변경·운전·경보를 시각·주체와 함께 저장(분쟁·A/S 근거)
6. **열린 연동** — 외부 장비는 Modbus, 로봇은 VDA 5050, 클라우드는 MQTT·REST API

## 6. 하드웨어 표준 (안)

| 구분 | 표준안 | 비고 |
|---|---|---|
| 엣지 컨트롤러 | 산업용 Linux 보드 (예: Raspberry Pi CM4/CM5 산업용 캐리어, 팬리스 IPC) | 1호 농장은 Pi 3B+(실내). eMMC·RTC·워치독·DIN 레일·UPS 권장 |
| 현장 통신 | **Modbus TCP** (필드 함체 게이트웨이 또는 이더넷 릴레이 보드) | 이더넷 100 m 초과 구간은 광 컨버터. 시운전·근거리는 절연형 USB-RS485 허용 |
| 출력 | RS485/이더넷 Modbus 릴레이 보드 → **전자접촉기(MC)** → 부하 | Pi GPIO(3.3V 비절연)는 사용하지 않음 (2026-11-07 결정) |
| 센서 | RS485 Modbus 센서 | 국번 중복 금지, 데이지체인, 120 Ω 종단, 차폐 트위스트 페어 |
| 제어망 | 전용 스위치/VLAN, 엣지에 별도 NIC | Modbus TCP 는 인증이 없으므로 인터넷·일반망 비노출 |
| 전원 | 제어 전원 24 VDC, 엣지·네트워크 UPS | 정전 감지 → 알림·안전 종료 |
| 함체 | IP65 이상, 서지 보호기(전원·통신), 비상정지 스위치 | 표준 도면·부품 목록(BOM)으로 대리점 시공 가능하게 |

## 7. 소프트웨어 구조

### 엣지 (현재 저장소를 발전)
| 모듈 | 현재 | 제품화 작업 |
|---|---|---|
| 측정 루프 | `smartfarm.main` (10초 측정, 30초 저장) | 장치 프로파일 기반 센서 드라이버(Modbus) |
| 제어 엔진 | `smartfarm.control.engine` (1초 주기) | 계층형 모델, 시스템 구성 설정화, 레시피 실행 |
| 출력 드라이버 | mock, gpio | **Modbus TCP/RTU 드라이버**, 통신 감시·상태 재확인 |
| 저장 | SQLite (`smartfarm.db`, `control.db`) | 보존 정책·용량 관리, 클라우드 동기화 대기열 |
| 웹/HMI | 표준 라이브러리 HTTP 서버, 정적 JS | 설치자 도구(I/O 할당·시운전), 현장 터치 HMI |
| 알림 | 텔레그램 | 클라우드 앱 푸시로 확장(텔레그램은 옵션 유지) |
| 원격 접속 | Tailscale (Funnel 공개 페이지) | 클라우드 MQTT 연결로 대체·보완 |

### 클라우드 (신규)
- 기기 등록·인증서 발급, MQTT 브로커, 시계열 DB, 사용자·농장·권한, 앱 API
- 모바일 앱(농장주), 관리 콘솔(본사·대리점), OTA 배포(서명·단계적 배포·롤백)

### 개발 원칙
- 모든 제어 로직에 자동 테스트(현재 80개) — 실제 출력 없이 가짜 시계·모의 출력으로 검증
- 실제 출력 시험은 반드시 설치자 도구의 시운전 절차로(릴레이 단위 확인 → 구역 단위 → 자동)

## 8. AGV 통합

| 항목 | 방침 |
|---|---|
| 책임 분리 | 주행·위치 추정·장애물 회피·비상정지는 **AGV 자체**. 플랫폼은 작업 지시·감시·스케줄 |
| 인터페이스 | **VDA 5050** (MQTT 기반 AGV 표준) — 자체·타사 AGV 를 같은 방식으로 연결 |
| AGV 소프트웨어 (자체 개발 시) | ROS 2 + Nav2 기반 권장 |
| 설비 연동 예 | 관수·방제 중인 구역 진입 금지, 작업 완료 후 관수 시작, 충전 스케줄과 야간 작업 조정 |
| 도입 순서 | ① 순찰·작물 촬영 → ② 운반(수확물·자재) → ③ 방제 → ④ 수확 보조 |
| 안전 | 사람과 같은 공간 주행 → 속도 제한·구역 설정·비상정지, 관련 안전 규격 검토(10장) |
