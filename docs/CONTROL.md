# 구역 제어 (관수·양액·조명·공조팬·히터)

웹 제어 화면: **https://smartfarm-pi.tail084a13.ts.net/control** (관리자 로그인 필요)
공개 현황 페이지 아래 "구역 현황"에는 구역별 켜짐/꺼짐만 보인다.

> **현재는 시뮬레이션(mock) 모드** — 릴레이가 연결되지 않아 실제로는 아무것도 켜지지 않는다.
> 스케줄·온도 조건·대기열·리포트는 실제와 똑같이 동작하므로 미리 설정하고 시험할 수 있다.

## 1. 시스템 구성

| 시스템 | 구역 | 동작 방식 | 수동 운전 |
|---|---|---|---|
| 관수 | 8 + 주 펌프 | 스케줄(시작 시각 + N분, 요일). **동시 관수 구역 수 제한**(기본 1) → 나머지는 대기열로 순서대로. 관수 중 주 펌프 자동 ON | N분 (1~120분, 필수) |
| 양액 | 6채널 | 원수 보충 밸브, A액·B액 펌프, pH 조절(산) 펌프, 교반기, 공급 펌프. **EC/pH 자동 투입**(아래) | 투입 펌프 1~120초 / 나머지 1~120분 |
| 조명 | 8 | 스케줄 시간대(예: 06:00~18:00, 자정 넘김 가능)에 ON | 계속 또는 N분 |
| 공조팬 | 8 | 스케줄 시간대 **또는** 온도 ≥ 설정온도+편차 → ON, 설정온도 이하 → OFF | 계속 또는 N분 |
| 히터 | 8 | 온도 ≤ 설정온도−편차 → ON, 설정온도 도달 → OFF. 스케줄을 넣으면 그 시간대에만 | N분 (1~240분, 필수) |

각 구역 카드 버튼: **켜기/관수**(시간 입력) · **끄기/중지** · **자동**(수동 해제) · **설정**(이름, 사용 여부, 스케줄, 온도센서·설정온도·편차, 유량, 과열 차단 온도)

### 양액 자동 투입
1. EC < 목표−편차 → A·B 액을 `1회 투입(초)` 만큼 동시에 넣고 교반기 ON
2. `교반 대기(초)` 동안 기다린 뒤 다시 측정 (조금씩 여러 번 → 과다 투입 방지)
3. EC 정상이면 pH > 목표+편차일 때 산을 같은 방식으로 투입
4. EC 가 목표보다 높으면 텔레그램 "원수 보충 필요" 알림(자동 희석은 수위센서 연결 후)
5. 하루 최대 투입 횟수에 도달하면 멈추고 알림
- **EC/pH 센서가 모의값이면 자동 투입하지 않는다**(현재 상태).

## 2. 안전 장치

- 시작·종료·**전체 정지** 시 모든 출력 OFF. 재시작하면 수동 운전·관수 대기열은 이어가지 않는다.
- 히터: 센서 값 없음/모의값/60초 이상 갱신 없음 → **즉시 OFF + 텔레그램 알림**.
  **과열 차단 온도**(기본 35 °C) 이상이면 수동 켜기 중이라도 OFF.
- 팬·히터 자동 전환은 최소 켜짐/꺼짐 시간(팬 60초, 히터 120초)을 지켜 짧은 반복 동작 방지.
- 웹 명령은 대기열을 거쳐 1초 안에 실행. 60초 넘게 처리되지 않은 명령은 버린다
  (측정 서버가 꺼져 있다가 켜지며 옛 명령을 실행하는 일 방지).
- 실제 출력 드라이버(mock 아님)를 쓰는 동안 **4자리 PIN 로그인으로는 제어 불가** → 10자 이상 비밀번호 필요.
- 모든 설정 변경·명령은 `control.db` 의 `events` 에 기록.

## 3. 리포트

제어 화면 **리포트** 탭: 기간(오늘/7/30/90일)별
- 일별 관수 시간 막대그래프, 구역별 합계(횟수·운전 시간·물 사용량*), 최근 운전 기록 100건
- **CSV 내려받기**(엑셀에서 바로 열림)
- 기록 항목: 시스템, 구역, 시작/종료, 운전 시간, 방식(스케줄·수동·온도·자동), 결과(완료·중지·중단)

\* 관수 구역 설정에 **유량(L/분)** 을 넣으면 사용량 계산.

## 4. 구조

```
웹 제어 화면 ──POST──▶ 웹서버(smartfarm-web) ──명령·설정──▶ data/control.db ◀── 제어기 스레드
     ▲                                                                 (smartfarm 측정 서버 안, 1초 주기)
     └──GET── 상태 ◀── data/control.json ◀──────────────────────────────┘   │
                                                       센서값 ◀── 측정 루프(10초) │
                                                       출력 ──▶ 드라이버(mock/gpio/…)
```

| 파일 | 역할 |
|---|---|
| `src/smartfarm/control/systems.py` | 시스템·구역 정의, 기본값, 설정 검증 |
| `src/smartfarm/control/engine.py` | 제어기(판단·안전·대기열·양액 상태기계) |
| `src/smartfarm/control/store.py` | control.db (설정, 명령, 운전 기록, 이벤트) |
| `src/smartfarm/control/outputs.py` | 출력 드라이버 (mock, gpio) |
| `src/smartfarm/web/control_api.py` | 웹 API |
| `src/smartfarm/web/static/control.html/js` | 제어 화면 |
| `tests/test_control.py` | 23개 테스트 |

## 5. 하드웨어 연결 (결정 필요)

출력이 **39개**(관수 8 + 주 펌프 1, 양액 6, 조명 8, 팬 8, 히터 8)라 Pi GPIO(약 26개)로는 부족하다.

| 방식 | 장점 | 단점 |
|---|---|---|
| **RS485 Modbus 릴레이 보드**(8/16/32채널) — 권장 | 배선 길이 수백 m, 보드 여러 개를 한 선으로 연결, 산업용 제품 많음, 구역별 분전반 배치 쉬움 | USB-RS485 변환기 필요 |
| I2C 확장(MCP23017, 16출력) + 릴레이 모듈 | 저렴 | 배선 1~2 m 이내, 노이즈에 약함(현장 배선엔 부적합) |
| Pi GPIO 직접 | 이미 코드 있음(gpio 드라이버) | 개수 부족 |

전기 주의: 히터·팬·조명은 **릴레이 접점 용량 이상의 부하는 반드시 전자접촉기(MC)** 로 구동,
히터에는 **독립 기계식 과열 차단기(바이메탈)** 를 함께 설치(소프트웨어 차단과 별개).
관수 밸브는 보통 AC24V 솔레노이드 → 24V 전원 + 릴레이.

하드웨어가 정해지면 `outputs.py` 에 드라이버를 추가하고 `config.yaml` 의 `control.channels` 에서 채널을 매핑한다.

## 6. 추가로 필요한 시스템 (조사·제안)

우선순위 높음 = 위 시스템이 안전하게 동작하려면 필요한 것.

| 우선 | 시스템 | 이유 / 하는 일 | 필요 장비 |
|---|---|---|---|
| ★★★ | **구역별 온습도 센서** | 히터·팬 8구역을 따로 제어하려면 구역마다 온도가 필요(현재 온도센서 3개). 습도도 함께 | 구역당 SHT31/SHT45 또는 RS485 온습도 센서 |
| ★★★ | **물탱크 수위** | 양액 탱크 공회전·넘침 방지, 원수 자동 보충, 펌프 보호 | 플로트 스위치(상/하) 또는 초음파 수위센서 |
| ★★★ | **유량·압력 센서** | 관수가 실제로 됐는지 확인(밸브 고장·배관 막힘·누수 감지), 사용량 실측 | 펄스 유량계, 압력 트랜스미터 |
| ★★★ | **정전·전원 감시 + UPS** | 정전 시 텔레그램 알림, Pi 안전 종료(SD 카드 손상 방지) | 소형 UPS(HAT) |
| ★★ | **토양(배지) 수분 센서** | 시간 대신 수분 기준 관수, 과습 방지 | 구역당 정전용량식/TDR 센서 |
| ★★ | **CO₂ 센서·공급** | 광합성 시간대 CO₂ 보충(시설재배 수확량 향상), 환기와 연동 | NDIR CO₂ 센서, CO₂ 밸브 |
| ★★ | **천창·측창 개폐 / 차광 커튼** | 자연 환기·고온기 차광, 바람·비 올 때 닫기 | 개폐 모터(정·역 2출력 + 리밋) |
| ★★ | **가습(포그)·제습** | 습도 40~80% 유지 | 포그 노즐 밸브, 제습기 |
| ★★ | **외부 기상**(온도·풍속·강우) | 바람·비에 창 닫기, 외기 온도로 환기 판단 | 기상 센서 또는 기상청 API |
| ★ | **배액 EC/pH·배액량** | 양액 농도 보정 근거 | EC/pH 센서, 배액 계량기 |
| ★ | 순환팬(유동팬) | 공조팬과 별도로 내부 공기 순환 | 릴레이 |
| ★ | 카메라 | 원격 육안 확인, 타임랩스 | Pi 카메라/IP 카메라 |
| ★ | 출입·누수·화재 감지 | 보안·재해 알림 | 접점 센서 |

코드 구조상 **켜기/끄기 + 스케줄 + 센서 기준** 형태(순환팬, 가습, 제습, CO₂ 밸브 등)는
`systems.py` 에 시스템을 추가하는 것만으로 같은 화면·리포트에 들어간다.
창·커튼(정/역 모터)과 수위·유량 연동은 별도 로직이 필요하다.

## 7. 다음 단계 제안

1. **하드웨어 방식 결정** (RS485 Modbus 권장) → 드라이버 추가 → 관수 1구역으로 실물 시험
2. 운영 전 **관리자 비밀번호 10자 이상으로 변경** (실제 출력이 연결되면 PIN 제어가 막힘)
3. 구역별 온습도 센서 → 히터·팬 구역 매핑
4. 수위·유량 센서 → 양액 자동 보충, 관수 확인
5. 습도/pH/EC 실제 드라이버 → 양액 자동 투입 활성화
